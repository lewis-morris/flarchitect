## Findings

### F-01 — Bound and reuse pure field-name conversions (minor, moderate)
- **File:** flarchitect/utils/core_utils.py:9-45
- **Category:** backend-efficiency
- **Problem:** `re.findall(...)`, lowercasing and six converter closures are repeated for identical `(s, target_case)` pairs throughout schema and response handling.
- **Why it matters:** Model and envelope names repeat across requests, so the same pure computation runs indefinitely.
- **Fix direction:** Preserve the existing conversion body as a private uncached helper. Add a private `lru_cache(maxsize=4096)` helper delegating to it. Public `convert_case` uses the cache only for exact built-in str inputs with both lengths at most 256; all other inputs delegate directly to the unchanged implementation. Keep public signature/docstring and wrapper helpers. Avoid caching request configuration or mutable objects.
- **Behavior risk:** Preserve empty/punctuation strings, acronyms, numbers, Unicode, unknown styles and existing unusual-input exceptions. Bypass cache for subclasses, non-strings and long strings. Test exact expected outputs, legacy differential corpus, bounds/eviction and bypass. No application state is part of conversion.

### F-02 — Resolve the envelope naming style once (minor, trivial)
- **File:** flarchitect/utils/response_helpers.py:133-135
- **Category:** backend-efficiency
- **Problem:** The response dict comprehension resolves `API_FIELD_CASE` separately for every key.
- **Why it matters:** The representative response repeats the same lookup eight times; larger envelopes repeat it more.
- **Fix direction:** After `_filter_response_data`, read the setting once into a local and pass that local to every convert_case call. Preserve filtering, final callback position, content negotiation and status behavior exactly.
- **Behavior risk:** Case can differ between requests; never cache it across requests. Verify all six cases, default/unknown styles, JSON/XML, filtering, error payloads, callback order and request isolation. Existing XML status behavior is preserved, not corrected here.

- Nested-input schema construction savings depend on field order/cache state; not confirmed enough to change.

Response construction is about 29% faster in this local component benchmark. This does not establish whole-endpoint or production throughput. Timings are subject to machine load; lookup counts independently establish removed work.

**Trade-off:** cycling through 6,000 unique names (more than the 4,096-entry cache) took 10.332 ms before and 11.514 ms after, roughly 11% slower from cache bookkeeping. Outputs still match. The intended benefit is repeated model/envelope names; highly variable unique strings do not benefit. Inputs over 256 characters and non-exact-string inputs bypass the cache, and tests prove the 4,096-entry limit and eviction behavior. Raw cold-cache measurements are saved in `cold-cache.json`.
